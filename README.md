# Docker Images Pusher

使用Github Action将国外的Docker镜像转存到阿里云私有仓库，供国内服务器使用，免费易用<br>
- 支持DockerHub, gcr.io, k8s.io, ghcr.io等任意仓库<br>
- 支持最大40GB的大型镜像<br>
- 使用阿里云的官方线路，速度快<br>

## 使用方式


### 配置阿里云
登录阿里云容器镜像服务<br>
https://cr.console.aliyun.com/<br>
启用个人实例，创建一个命名空间（**ALIYUN_NAME_SPACE**）
![](/doc/命名空间.png)

访问凭证–>获取环境变量<br>
用户名（**ALIYUN_REGISTRY_USER**)<br>
密码（**ALIYUN_REGISTRY_PASSWORD**)<br>
仓库地址（**ALIYUN_REGISTRY**）<br>

![](/doc/用户名密码.png)


### Fork本项目
Fork本项目<br>
#### 启动Action
进入您自己的项目，点击Action，启用Github Action功能<br>
#### 配置环境变量
进入Settings->Secret and variables->Actions->New Repository secret
![](doc/配置环境变量.png)
将上一步的**四个值**<br>
ALIYUN_NAME_SPACE,ALIYUN_REGISTRY_USER，ALIYUN_REGISTRY_PASSWORD，ALIYUN_REGISTRY<br>
配置成环境变量

### 添加镜像
打开images.txt文件，添加你想要的镜像 
可以加tag，也可以不用(默认latest)<br>
可添加 --platform=xxxxx 的参数指定镜像架构<br>
可使用 k8s.gcr.io/kube-state-metrics/kube-state-metrics 格式指定私库<br>
可使用 #开头作为注释<br>
![](doc/images.png)
文件提交后，自动进入Github Action构建

### 使用镜像
回到阿里云，镜像仓库，点击任意镜像，可查看镜像状态。(可以改成公开，拉取镜像免登录)
![](doc/开始使用.png)

在国内服务器pull镜像, 例如：<br>
```
docker pull registry.cn-hangzhou.aliyuncs.com/shrimp-images/alpine
```
registry.cn-hangzhou.aliyuncs.com 即 ALIYUN_REGISTRY(阿里云仓库地址)<br>
shrimp-images 即 ALIYUN_NAME_SPACE(阿里云命名空间)<br>
alpine 即 阿里云中显示的镜像名<br>

### 多架构
需要在images.txt中用 --platform=xxxxx手动指定镜像架构
指定后的架构会以前缀的形式放在镜像名字前面
![](doc/多架构.png)

### 镜像重名
程序自动判断是否存在名称相同, 但是属于不同命名空间的情况。
如果存在，会把命名空间作为前缀加在镜像名称前。
例如:
```
xhofe/alist
xiaoyaliu/alist
```
![](doc/镜像重名.png)

### 定时执行
修改/.github/workflows/docker.yaml文件
添加 schedule即可定时执行(此处cron使用UTC时区)
![](doc/定时执行.png)

### 自动跟踪上游版本（vllm / sglang）

`latest` 是不可复现的浮动标签——每天同步了，却不知道它到底对应哪个版本。本项目额外提供一套**版本号自动发现**机制来解决这个问题：

- `config/tracked-images.yaml`：要跟踪哪些镜像、时间窗（默认 90 天）、版本分组粒度、最多保留几个版本、变体白名单。
- `scripts/update_images.py`：调用 Docker Hub API 拉 tag 列表，用 `latest` 的 digest **反查**出它对应哪个版本号（不靠猜后缀），再按时间窗与分组规则挑出要保留的版本。
- `.github/workflows/update-versions.yaml`：每天 04:17（北京时间）自动跑上面的脚本。

脚本只会改写 `images.txt` 里被托管的 **managed 块**，块外内容一律不动：

```
# >>> BEGIN managed: docker.io/vllm/vllm-openai >>>
# generated by scripts/update_images.py; do not edit manually
vllm/vllm-openai:latest
vllm/vllm-openai:v0.31.0
vllm/vllm-openai:v0.30.0
vllm/vllm-openai:v0.29.0
# <<< END managed: docker.io/vllm/vllm-openai <<<
```

于是阿里云仓库里会**同时存在** `:latest` 和 `:v0.31.0` 这类带版本号的 tag，既能跟随最新，也能锁定可复现的版本。

版本筛选规则：
- 只保留最近 **90 天**内更新过的版本（`latest` 当前指向的那个版本不受此限）。
- 分组粒度按镜像分别配置：`vllm` 是 `minor`（0.30 → 0.31），`sglang` 是 `patch`（0.5.20 → 0.5.21），同组只保留版本最高的一个。
- 每个镜像最多保留 `max_versions`（默认 **3**）个版本行，取版本号最高的几个。`latest` 指向的那个版本必定保留——若它被截掉，会挤掉最低位的那个。
- 变体**白名单**：后缀不在 `preferred_variants` 里的 tag 一律不参与选版。这样 `-rocm700-ml35x`（AMD ROCm 构建）、`-lmslim` 这类异种 tag 不会因为 `.postN` 版本号更高而被误选。
- 反查不到 `latest` 对应版本时 **hold**：本轮不动，等下一轮再试，绝不猜。

> 注意 `workflow_dispatch` 的 `dry_run` 是**布尔**输入。判断"非 dry-run"必须写 `!inputs.dry_run`，
> 不能写 `inputs.dry_run != 'true'` —— GitHub 表达式跨类型比较会转成数字（`true`→1、`'true'`→NaN），
> `1 != NaN` 恒为真，结果勾了 dry_run 也会去执行提交步骤。

注意事项：
- **不要手动编辑 managed 块**，改动会在下次运行时被覆盖。
- 想把某个镜像纳入托管：在 `config/tracked-images.yaml` 的 `images` 下加一项即可。
- 想手动跑一次：Actions → `Update image versions` → Run workflow（可勾选 `dry_run` 只打印不写盘）。
- **旧版本 tag 不会从阿里云自动删除**。某版本超出保留范围后只是不再出现在 `images.txt` 里。ACR 个人版**不支持**自动清理，需手动去控制台删（见文末「阿里云 ACR 个人版限制与旧镜像清理」）。
- `GITHUB_TOKEN` 触发的 push 不会自动触发其它 workflow，所以 `update-versions.yaml` 提交后会**显式调用** `Docker` workflow 去同步镜像。

### 阿里云 ACR 个人版限制与旧镜像清理

本项目使用 ACR **个人版**（免费）。它的实际限制如下（2026-10 查证）：

| 项目 | 个人版实际情况 |
|---|---|
| 镜像总存储容量 | **无总量上限**（个人版免费，上传/拉取镜像均免费，未设总容量配额） |
| 命名空间 | **3 个** |
| 镜像仓库数 | **300 个** |
| 单镜像大小 | 文档在函数计算场景给出「未解压 ≤3 GB，部分地域 10 GB」，**是否作用于 ACR 推送本身需自行确认** |
| 生命周期自动清理 | 不支持（企业版才有） |
| OpenAPI | 不提供（个人版不支持 API 操作） |
| SLA | 无 |

结论：**容量不缺，缺的是"自动清理"能力。**

#### 旧镜像怎么清理

个人版**没有可配置的自动清理**：生命周期规则（`CreateArtifactLifecycleRule`）与删除接口（`DeleteRepoTag`）都要求 `InstanceId`，那是企业版实例才有的东西。

手动删除路径：

> ACR 控制台 → 镜像仓库 → 选中仓库 → 版本列表 → 删除指定 tag

如果将来想自动化，先实测个人版是否开放标准 registry v2 删除接口（官方未承诺支持，大概率被禁）：

```bash
curl -i -X DELETE -u "<username>:<password>" \
  -H "Accept: application/vnd.docker.distribution.manifest.v2+json" \
  "https://<registry>/v2/<namespace>/<repo>/manifests/<digest>"
```

返回 `202` 才说明可用；否则只能升级企业版。
